## FIX 1 (MAJOR, F-01) — `location/LocationRepository.kt` timeout detection must be deterministic
`if (nowMs() - before >= remaining) timedOut = true` compares a wall clock against a snapshot budget, so a
provider that concludes its own budget early is reported as NO_FIX instead of TIMEOUT.
Replace it with an "attempt completed" flag set INSIDE the `withTimeoutOrNull` lambda, e.g.
```kotlin
var completed = false
val fix = try { withTimeoutOrNull(remaining) { source.current(kind, remaining).also { completed = true } } }
          catch (_: Exception) { null }
if (!completed) timedOut = true
```
so TIMEOUT means "this attempt's budget fired (or the provider never answered)", never a clock comparison.
Keep the existing stale-cache and outer-timeout behaviour intact.

## FIX 2 (MAJOR, F-02) — no hidden budget cut; NETWORK must always get its turn
`AndroidPlatformLocationSource.current` silently halves the timeout it is given for FUSED/GPS
(lines ~59-63), which the pure repository cannot see. Move the per-kind budget decision into
`BestAvailableLocationRepository` and pass that explicit budget down: the Android source must use exactly the
`timeoutMs` it receives (no internal `/2`). Suggested allocation in the repository: FUSED = half of the
remaining budget, GPS = half of what is left, NETWORK = all of what is left, each at least 1 ms, and never
exceed the overall budget.
Add a regression test: FUSED and GPS each consume their full allocated budget and return null while a NETWORK
fix exists → NETWORK IS attempted and its fix is returned (assert the attempted kinds in order and the
returned `LocationSource`).

## FIX 3 (MAJOR, F-04) — `AndroidPlatformLocationSource` must never throw

Add/extend a test with a source whose `lastKnown()`/`enabledProviders()` throw, asserting a clean failure

## FIX 4 (MAJOR, F-09) — `emergency/AndroidSimCallGateway.kt` must not call startActivity off the main thread

One attempt only, never a retry, and no more than one dial per SOS event.
