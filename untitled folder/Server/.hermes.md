# NCKH27VK — Điều khoản số 1: Quy trình Git bắt buộc

Áp dụng cho mọi tác vụ sửa/thêm code, tạo file, sửa cấu hình hoặc cập nhật tài liệu trong repository này.

Repository chính thức: https://github.com/phandinhdoc-spec/nckh27vk.git
Nhánh phát hành bắt buộc: `main`.

## Điều kiện hoàn thành

Chỉ xem một tác vụ là HOÀN THÀNH khi đã:

1. Thực hiện xong công việc.
2. Chạy kiểm tra, test hoặc build phù hợp và chỉ coi là hoàn thành khi kết quả hợp lệ.
3. Kiểm tra `git diff` và `git status`.
4. Rà soát thay đổi trước khi staging để không commit API key, token, mật khẩu, `.env` chứa secret, build artifact/cache lớn hoặc dữ liệu thử nghiệm không công khai.
5. Commit thay đổi có ý nghĩa.
6. Push thành công lên `origin main` của repository chính thức.

Không được dừng ở trạng thái chỉ sửa code, tạo file hoặc pass test nhưng chưa push GitHub.

## Quy trình mặc định

Sau mỗi đơn vị công việc hợp lý (không phải từng thay đổi nhỏ):

```bash
git status
git diff --check
# Rà soát danh sách file trước khi staging; cập nhật .gitignore nếu cần.
git add -A
git commit -m "<mô tả ngắn gọn, rõ ràng về thay đổi>"
git push origin main
```

Nếu `origin` chưa đúng, đặt lại bằng:

```bash
git remote set-url origin https://github.com/phandinhdoc-spec/nckh27vk.git
```

Nếu test/build thất bại, không commit/push như công việc hoàn tất: tiếp tục sửa. Chỉ dùng commit WIP khi thật sự cần lưu tiến độ chưa hoàn chỉnh và phải ghi rõ WIP.

## Báo cáo kết thúc

Nêu ngắn gọn: thay đổi đã làm; test/build đã chạy và kết quả; commit hash; xác nhận push thành công; nhánh đã push.

Yêu cầu cụ thể mới nhất của người dùng được ưu tiên nếu mâu thuẫn với quy tắc này.

# NCKH27VK — Điều khoản số 2: Điều phối tác vụ bằng cmd-orchestrator

Áp dụng cho mọi tác vụ trong project này. `cmd-orchestrator` là plugin điều phối chính và chế độ mặc định là tự động điều phối; người dùng không cần gọi plugin trong từng yêu cầu.

## Khi nào phải điều phối

Trước mọi tác vụ không đơn giản, dùng `cmd-orchestrator` để phân tích và điều phối. Tác vụ nhỏ, rõ ràng, cơ học (đổi tên, sửa text đơn giản, tìm kiếm, formatting hoặc chỉnh sửa nhỏ) có thể thực hiện trực tiếp khi chi phí điều phối cao hơn chi phí làm việc; không tạo worker hoặc DAG phức tạp không cần thiết.

Với tác vụ phức tạp, áp dụng pipeline phù hợp:

```text
TaskClassifier
→ grill-tab / prompt refinement khi thực sự cần
→ machine-readable plan
→ dependency graph
→ model routing
→ workers
→ verify/test
→ retry/escalate khi cần
→ record routing result
→ hoàn thành
```

`grill-tab` chỉ là công cụ phân tích/refine prompt. Chỉ dùng khi yêu cầu còn mơ hồ, tác vụ lớn, cần phân rã nhiều nhánh, hoặc lập kế hoạch trước giúp giảm lỗi/tổng token.

## Trách nhiệm của cmd-orchestrator

Plugin phải phân loại tác vụ; quyết định phần Hermes làm trực tiếp hay cần chia nhỏ; tạo plan/DAG và dependency khi cần; chọn provider, model và reasoning level; gọi worker; kiểm tra kết quả thực tế; retry hoặc đổi model khi cần; và ghi nhận kết quả thực tế để cải thiện routing.

Thứ tự ưu tiên: (1) chính xác, (2) phân rã hợp lý không vụn, (3) tiết kiệm chi phí/token. Không hy sinh độ chính xác chỉ để dùng model rẻ hơn.

Chọn model rẻ nhất vẫn đủ khả năng hoàn thành đáng tin cậy. Chỉ tăng cấp sau khi verification thất bại. Không dùng model mạnh cho thao tác cơ học.

Tận dụng credential pool CommandCode hiện có. Provider/Hermes quản lý rotation và failover credential; plugin chỉ quyết định provider, model, reasoning level và task routing. Không hard-code API key trong plugin hoặc source code.

Không để worker tự tạo worker vô hạn: phải có recursion guard và giới hạn mức phân rã.

Sau mỗi worker, kiểm tra output, file thực tế và test/build phù hợp; không tin hoàn toàn vào tự báo "done". Khi model thất bại, retry hợp lý, sau đó chuyển model/provider khác và lưu kết quả routing.

Giữ context của worker tối thiểu: chỉ đọc file cần thiết, ưu tiên công cụ tìm kiếm/đọc có mục tiêu; không quét toàn repository nếu không cần.

Lệnh điều khiển/debug chỉ dùng khi người dùng muốn xem hoặc can thiệp quá trình điều phối.

## Hoàn tất GitHub

Chỉ sau khi toàn bộ công việc được verify thành công mới áp dụng Điều khoản số 1: kiểm tra diff/status; chạy test/build phù hợp; commit; push `main` lên https://github.com/phandinhdoc-spec/nckh27vk.git. Chỉ báo DONE sau khi push thành công.

Quy tắc này là mặc định lâu dài cho NCKH27VK; không cần nhắc lại ở mỗi prompt.
